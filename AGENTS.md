# engine

A Go library (`gitlab.com/kickr-dev/engine`) to build project scaffolding CLIs.
Its three parts are `Initialize` (a huh form), parsers (repository detection) and `Generate` (files from Go templates).

The [README.md](README.md) explains the generation flow and file policies with diagrams, and lists the helper packages.
Read it before changing that flow, a policy or a helper package,
and update it with the change.
The [CONTRIBUTING.md](CONTRIBUTING.md) holds the commit types and their release impact.

## Packages

- `pkg/` is package `engine`, imported as `engine "gitlab.com/kickr-dev/engine/pkg"`.
- `pkg/` holds `Initialize`, `Generate`, `Template`, the policies, sections, patches and template funcs.
- `pkg/files` reads and writes JSON, TOML and YAML, validates JSON schemas, globs files and reads the umask.
- `pkg/generator` fetches remote content (`.gitignore`, code of conduct, container images) for an `engine.Generator`.
- `pkg/parser` detects Git, Go, Hugo and `package.json`, and merges Helm values, for an `engine.Parser`.
- `testutils/` holds test helpers, exported for consumers' tests too.

## Generation

- Parsers run one after the other, so each one can enrich the config for the next.
- Generators run concurrently, so a generator must be safe for concurrent use and share no mutable state.
- A generator logs its own errors and returns `ErrFailedGeneration`, and `Generate` logs any other error.
- Run settings travel in the context (`ContextWithOptions`), never in package state.
- The only global is the logger (`SetLogger`, `GetLogger`), stored in an `atomic.Pointer`.
- Every write goes through the `*os.Root` given to the generator, so no template can escape the destination.
- An unchanged output file is never rewritten, to keep its mtime.
- Keep that check in any new write path.
- Templates get the Sprig hermetic funcs only (no env, network, date or random funcs), so output stays reproducible.
- New template funcs go in `FuncMap` in `pkg/template_funcs.go`.

## File ownership

`IsGenerated` decides whether a file gets overwritten, through the `notice` regexp in `pkg/generate_policy.go`.
A file is owned by generation when it's missing, empty,
or has `Code generated by <tool>; DO NOT EDIT.` in its first 3 lines.

- Changing `notice` changes which user files get overwritten in every consumer repository.
- `IsEmpty` and `Options.StripMarkers` match the same `notice`, so they move with it.
- Policy semantics live in the GoDoc of the `GeneratePolicy` constants.
- `PolicyRemove` and `PolicySkip` ignore `Options.Force`.
- A policy change updates that GoDoc and the README templates diagram.

## Public API

- Every exported identifier is public API.
- Removing or renaming one is a breaking change.
- `.releaserc.yml` releases a breaking commit as a major version, and the next major is v1.0.0.
- A behavior change updates the GoDoc, the matching `doc.go` example and the README together.

## Tests

- Test files use the external package (`engine_test`, `parser_test`).
- Only tests of unexported code use the internal package, with a `//nolint:testpackage` on the `package` line.
- Open an `*os.Root` with `testutils.Root(t, dir)`, which closes it on cleanup.
- Mock HTTP with `httpmock.Activate()` at the top of the test func, then `t.Cleanup(httpmock.DeactivateAndReset)`.
- `httpmock.Activate` swaps the `http.DefaultTransport`, so pass `http.DefaultClient` to the fetchers.
- No test reaches the network.
- A test calling `SetLogger` restores the previous logger with `t.Cleanup`.

## Checks

- Run `just test`.
- Run `just test-race` after touching `Generate`, `GeneratorModules` or the logger.
- `just test-race` needs CGO, the recipe sets `CGO_ENABLED=1`.
- Run `just lint`, then read its output, because the recipe exits 0 even when golangci-lint fails.
- `.golangci.yml` enables every linter except a listed few, so expect `funlen` (80 lines, 60 statements) and revive's error string format.
- Fix a lint finding in the code, since kickr owns `.golangci.yml`.
- pre-commit (gitleaks, whitespace) runs on every commit, and CI also runs the Go tests and golangci-lint.

## Generated files

- kickr owns every file marked `Code generated by kickr; DO NOT EDIT.`, such as `Justfile`, `scripts/just/*.just`, `.golangci.yml` and `.gitlab/`.
- In `CONTRIBUTING.md` and `README.md`, kickr owns only the blocks between its `BEGIN_KICKR_*` and `END_KICKR_*` markers.
- Custom just recipes go in `scripts/just/custom.just`, which the `Justfile` imports when it exists.
- semantic-release writes `CHANGELOG.md`.
